# MORU COFFEE 촬영용 키오스크

2026-11-08 / codex-20261108-03. 기존 v2의 그림 중심 화면과 별도로, 상품 사진·행사 배너·가격·촘촘한 메뉴·옵션·주문내역을 넣은 **가상의 카페 화면**이다. 특정 매장 UI의 정확한 복제나 실측 자료가 아니다.

## 지금 테스트

**기존 실시간 촬영이 실행 중이면 서버를 다시 켤 필요가 없다.** PC에서 기존 `/host` 탭의 주소를 아래로 바꾼다(이전 `/host` 탭이 별도로 남아 있으면 정답 보고가 충돌하므로 닫는다).

`https://localhost:8443/kiosk/realistic/test-host.html`

휴대폰 `/cam`과 PC `/dash`는 그대로 둔다. 이 호스트는 새 키오스크의 화면 문자열을 기존 `/api/kiosk`에 **채점 전용**으로 보고한다. `MORU-portrait-B`로 기록해 이전 화면과 구분한다. 현재 화면 추출기가1080×1920으로 펴므로 이 연결의 기본은 **세로9:16**. 가로판은 별도 화면/OCR 시험용이며 현 분석기의 원근 보정 성능과 바로 비교하지 않는다. 자동 시간 전환을 포함하려면 호스트 주소에 `?timers=1`.

단독 화면만 열 때는 프로젝트 루트에서:

```powershell
python -m http.server 8780 --bind 127.0.0.1 --directory 04-practice-kiosk/realistic
```

- PC 가로 모니터: `http://localhost:8780/?format=landscape&layout=B&screen=menu&fixed=1`
- 세로 모니터·태블릿: `http://localhost:8780/?format=portrait&layout=B&screen=menu&fixed=1`
- 실제처럼 시간 초과·카드4초·완료10초 자동 전환도 시험하려면 `fixed=1`을 뺀다.
- 처음부터 주문하려면 `screen=menu`를 뺀다. `layout=A`도 가능.

**모니터에 이 화면을 띄우고 지금 사용하는 휴대폰 카메라→전송→분석 경로로 촬영한다.** 키오스크 페이지 자체는 휴대폰 영상을 받지 않는다. 기존 촬영·전송·분석 서버 구현은 수정하지 않았고, 별도 `test-host.html`만 채점 상태를 보고한다.

F11 전체 화면. `S` 또는 왼쪽 위3번 터치로 직원 메뉴, 전체 화면 버튼·배치·로그 저장. 모서리 표시는 기본 끔. 보정용이면 주소에 `&markers=1`. 타이머를 멈춘 `fixed=1`에서 카드 투입 화면은 자동 승인되지 않으므로 결제 전환 시험은 `fixed=1`을 빼거나 간편결제(모의)를 쓴다. 실거래 없음.

가로는1920×1080, 세로는1080×1920 논리화면을 비율 유지하며 창에 맞춘다. 16:10 등 다른 비율에서는 여백이 생긴다. 웹화면으로 실제 패널의 반사·시야각·PWM을 재현할 수는 없으며 **실제로 카메라로 촬영한 영상에서 확인**한다. 화면 효과로 가짜 반사·블러를 넣지 않았다.

## 기존 자료와 구분

- 상위 v2 4파일, batch-003, screen-map.v2, Codex 기존 목표 지도는 변경하지 않았다.
- 이 화면은 **다른 버튼 배치**이므로 기존 목표 좌표를 재사용하지 않는다. 촬영 분석에는 화면 영상만 입력한다. DOM·`currentMap`·터치 로그는 점검/채점에만 사용한다.
- 터치 로그 키는 `openkey-kiosk-realistic-v1`로 분리된다. 기존 v2 로그를 덮어쓰지 않는다.
- 정답 데이터로 수집하려면 별도 배치로 관리하고 카메라 원본·화면 크기·거치·시각을 함께 기록한다. 이 버전으로 모델을 학습하지 않았다.

## 사진 자산

`assets/cafe-products.png`: 내장 imagegen으로 만든 4×4 상품사진 atlas. CSS로 각 칸을 표시하며 이미지 파일을 편집·분할하지 않았다. 실제 메뉴 사진이 아니며 상품 이름과 함께 쓰는 시연 자산이다. 원본 URL 없이 로컬 제공, 실행 중 외부 이미지/CDN 호출 없음. 생성 프롬프트·파일 해시는 `assets/PROVENANCE.json`.
