# 실제 휴대폰 시험 절차 (아침에 팀이 할 것)

작성: 2026-11-12 / A(안내 실행부). 상태: **미시험 절차표**. 밤사이에는 PC 합성 시험만 했다(실제 휴대폰·카메라·사람 손은 한 번도 안 씀).
목적: 사용자가 **안내만 듣고 혼자** 시작부터 주문 번호까지 갈 수 있는지, 막히면 어디서 왜 막히는지 숫자로 적어 오기.
실행 방법은 [RUN.md](RUN.md). 숫자는 `https://localhost:8460/api/live`(또는 관리자 콘솔)에서 읽는다.

## 0. 준비물·역할

- 노트북(서버·키오스크 탭), 휴대폰 1대(안드로이드 Chrome 권장, 아이폰은 별도 칸에 기록), 휴대폰 거치대, 이어폰(선택), 안대(선택).
- 역할: **운영자**(노트북·기록), **사용자 역**(휴대폰 안내만 듣고 손을 움직임). 사용자 역은 키오스크 화면을 보지 않는 조건도 1회 이상.
- 영상 촬영은 하지 않는다(필요하면 화면 밖에서 손만, 팀 결정 후). 참가자는 `P01`처럼 코드로만 적는다.

## 4. 주문 끝까지 (단계별, 시도마다 10분 이내)

운영자는 화면을 가리키지 않는다. 사용자 역은 **안내만 듣고** 움직이고, "누르세요"에서 **직접 누른다**(노트북이 터치스크린이 아니면 자동 누름이 켜져 있음 — 키오스크 탭 주황 칸 확인, 기록에는 `auto_click`).

| 단계 | 기대 안내 | 확인 | 시도1 | 시도2 | 시도3 |
| --- | --- | --- | --- | --- | --- |
| 첫 화면 | "매장 버튼을 찾을게요" → 방향 → "멈추세요" → "누르세요" | 매장 눌림, "맞게 눌렀어요" | ☐ | ☐ | ☐ |
| 메뉴 | "메뉴 화면입니다. 아메리카노를 찾을게요" | 아메리카노 눌림 | ☐ | ☐ | ☐ |
| 옵션 | "옵션 화면입니다. 차가운 것, 아이스를 고를게요" → ICE → "다음은 담기 버튼입니다" | ICE·담기 | ☐ | ☐ | ☐ |
| 장바구니 | "장바구니에 담겼어요. 결제하기 버튼을 찾을게요" | 결제하기 | ☐ | ☐ | ☐ |
| 확인(금액) | 손이 보이면 "주문 확인 화면입니다. 금액을 확인할게요. 손을 잠시 내려 주세요" → 손 내림 → "…총 2,000원입니다…손을 다시 올려 주세요" | 손 내리기 전엔 "누르세요" 없음 | ☐ | ☐ | ☐ |
| 결제 | "결제 화면입니다…" → 손 내림 → "결제 금액은 2,000원입니다. 모의 결제예요. 간편결제…" | 간편결제 | ☐ | ☐ | ☐ |

## 6. 실패하면 적어 올 것

- 어느 단계·어느 안내 문구에서 멈췄는지(문구 그대로), 그때 `/api/live`의 `safety.reason`, `status.markers`, `status.hand_rate`, `finger.tracked`, `hand_down`.
- 기록 파일 이름: `07-demo/openkey-live/runs/<시도 ID>.jsonl`(관리자 콘솔 내보내기 또는 `/api/attempts`). 이 파일에는 영상이 없으니 그대로 공유해도 된다(참가자 코드만).
- 서버 창의 오류 줄, 키오스크 탭 왼쪽 상태 칸 문구.
- 휴대폰 기종·OS·브라우저, Wi-Fi 종류(학교/핫스팟).
- 소리 문제면: 첫 터치를 했는지, 무음 모드, 한국어 음성 여부.

## 7. 아직 모르는 것(이 시험으로 처음 확인)

- 실제 휴대폰 카메라에서 마커가 안정적으로 잡히는지(화면 반사·모아레·초점).
- 실제 손 인식률·지연(밤사이 수치는 합성 사진 시험이라 실제와 다를 수 있음, [tests/hand-eval/REPORT.md](tests/hand-eval/REPORT.md)).
- 손끝이 화면에서 떠 있을 때 시차로 버튼이 어긋나는 정도.
- 휴대폰 음성 속도와 서버의 말 길이 추정(글자당 0.12초)이 맞는지 — 말이 겹치거나 끊기면 적어 온다.
- 안대를 쓴 사람이 방향 안내만으로 버튼에 닿는지, 몇 초 걸리는지.
